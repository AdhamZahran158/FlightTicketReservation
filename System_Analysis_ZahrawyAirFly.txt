2. PROBLEM STATEMENT
================================================================================

Airlines worldwide need a unified, secure, and scalable platform that allows 
multiple airline companies to independently operate their booking systems under 
a single SaaS infrastructure. Each airline requires full control over:

  - Flight scheduling and route management
  - Aircraft fleet and seat configuration
  - Pricing, taxes, fees, offers, and discount policies
  - Booking, cancellation, and modification rules
  - Baggage weight limits and charges

Passengers need a seamless, visually immersive booking experience that includes 
an interactive airplane seat map simulation — where they can view the airplane 
interior, see available seats in real-time, select their preferred seat, and 
complete the booking process securely.

Current challenges in the market:
  1. Most systems lack true multi-tenancy with full data isolation
  2. Seat selection often lacks visual simulation of the airplane interior
  3. Security vulnerabilities in booking references allow tampering
  4. Limited real-time seat availability updates during peak booking periods
  5. Inflexible pricing models that don't support offers and discount codes

3. PROJECT OBJECTIVES
================================================================================

  1. Build a multi-tenant SaaS platform supporting multiple airline companies
  2. Implement complete flight management (CRUD, scheduling, routes)
  3. Create an interactive airplane seat simulation for visual seat selection
  4. Develop a robust booking engine with reserve, pay, modify, and cancel flows
  5. Build a flexible pricing engine supporting offers, discounts, taxes, and fees
  6. Implement strong security measures (JWT, CSRF, Rate Limiting, Encryption)
  7. Provide real-time seat updates using SignalR
  8. Integrate email notification system for booking confirmations
  9. Use Redis caching for high performance and fast response times
  10. Deliver a clean, maintainable codebase following SOLID and Clean Architecture

  FR-08  Each tenant has unique subdomain and branding (logo, company name)
  FR-09  Full data isolation between tenants (multi-tenant query filters)
  FR-10  Tenant-specific currency configuration
  FR-11  Tenant can manage its own admin and staff accounts

5.3 AIRPORT MANAGEMENT
------------------------
  FR-12  Super Admin can add/edit/delete airports
  FR-13  Each airport has IATA code, ICAO code, name, city, country, timezone
  FR-14  Airports have geographic coordinates (latitude, longitude)
  FR-15  Airport search by IATA code, city, or country
  FR-16  Airports are shared across all tenants (global resource)

5.4 AIRCRAFT & FLEET MANAGEMENT
---------------------------------
  FR-17  Airline Admin can add/edit/deactivate aircraft in their fleet
  FR-18  Each aircraft has model, registration code, seat configuration
  FR-19  Seat layout stored as JSON for flexible configuration
  FR-20  Define number of rows, seats per row, classes (Economy/Business/First)
  FR-21  Each seat has attributes: row, column, class, zone, window/aisle/exit

-----------------------
  FR-22  Airline Admin can create, update, cancel flights
  FR-23  Each flight links to aircraft, origin airport, destination airport
  FR-24  Flight has departure/arrival times (UTC), gate, terminal
  FR-25  Flight status management (Scheduled, Boarding, Departed, Arrived,

  FR-26  Set base prices per class (Economy, Business, First)
  FR-27  Configure baggage limits (max kg, free kg, extra per kg rate)
  FR-28  Flight search by origin, destination, date, class

5.6 SEAT MANAGEMENT & SIMULATION
-----------------------------------
  FR-29  Generate seat map per flight from aircraft seat configuration
  FR-30  Interactive airplane interior simulation (SVG-based)
  FR-31  Real-time seat status display (Available, Booked, Selected, Blocked)
  FR-32  Seat selection locks the seat temporarily via Redis (hold for 10 min)
  FR-33  Hover/click shows seat details (class, price, position, offer price)
  FR-34  Real-time updates via SignalR when seats are booked by other users
  FR-35  Seat price override capability per individual seat

5.7 BOOKING ENGINE
--------------------
  FR-36  Passenger can create a booking by selecting flight + seats
  FR-37  Booking generates encrypted, tamper-proof reference number
  FR-38  Passenger must agree to terms and conditions before booking
  FR-39  Booking stores passenger details per seat (name, passport)
  FR-40  Booking modification allowed if airline policy permits and deadline 
         not passed
  FR-41  Booking cancellation with configurable penalty percentage
  FR-42  Airline can cancel flights and auto-refund/compensate passengers
  FR-43  Full booking audit trail (BookingLog for every action)
  FR-44  Booking status flow: Pending -> Confirmed -> Modified -> Cancelled

5.8 PRICING ENGINE (OFFERS & DISCOUNTS)
------------------------------------------
  FR-45  Base price per class configured at flight level
  FR-46  Airline Admin can create time-limited Offers (% or fixed discount)
  FR-47  Offers can be linked to specific flights (many-to-many)

  FR-50  Final price calculation:

5.10 POLICY MANAGEMENT

  FR-57  Configure cancellation penalty percentage
  FR-58  Configure modification policy (allow/deny + deadline + fee)
  FR-59  Set terms and conditions text per airline

5.11 NOTIFICATION SYSTEM

         cancellation, modification, flight cancellation, payment receipt

5.12 DASHBOARD & ANALYTICS

7. USE CASE DESCRIPTIONS
================================================================================

USE CASE UC-01: SEARCH FLIGHTS
-------------------------------
  Actor       : Passenger
  Precondition: User is on the flight search page
  Flow:
    1. Passenger selects origin airport (IATA code or city name)
    2. Passenger selects destination airport
    3. Passenger selects travel date and class preference
    4. System queries available flights (with Redis cache)
    5. System displays matching flights with prices (including active offers)
    6. Passenger selects a flight to view details
  Postcondition: Flight details page is displayed

USE CASE UC-02: BOOK A SEAT
-----------------------------
  Actor       : Passenger
  Precondition: Passenger is logged in and viewing a flight
  Flow:
    1. System displays interactive airplane seat simulation
    2. Seat map shows real-time availability (via SignalR)
    3. Passenger hovers over seat to see price breakdown
    4. Passenger clicks seat to select it (locked for 10 min via Redis)
    5. Passenger enters passenger details (name, passport number)
    6. Passenger optionally enters discount code
    7. System calculates final price (Base - Offer - Discount + Tax + Fee)
    8. Passenger reviews booking summary and agrees to terms
    9. Passenger proceeds to payment
    10. System confirms booking and sends email notification
    11. System generates encrypted booking reference
  Postcondition: Booking is confirmed, seat is marked as booked

USE CASE UC-03: CANCEL BOOKING
---------------------------------
  Actor       : Passenger or Airline Staff
  Precondition: Booking exists and is in Confirmed status
  Flow:
    1. User navigates to booking details
    2. System checks airline's cancellation policy
    3. If cancellation allowed and before deadline:
       a. System calculates penalty (if any)
       b. System updates booking status to Cancelled
       c. System releases the seat(s)
       d. System initiates refund (total - penalty)
       e. System sends cancellation email notification
    4. If cancellation not allowed or past deadline:
       a. System shows error message
  Postcondition: Booking is cancelled, seat is released

USE CASE UC-04: MANAGE FLIGHTS (AIRLINE)
-------------------------------------------
  Actor       : Airline Admin
  Precondition: Admin is logged in to airline dashboard
  Flow:
    1. Admin navigates to flight management
    2. Admin creates new flight: selects aircraft, origin/destination airports,
       departure/arrival times, sets base prices, baggage policy
    3. System generates seat map from aircraft configuration
    4. Admin can optionally attach an active offer to the flight
    5. Admin publishes the flight (status: Scheduled)
  Postcondition: Flight is available for passenger booking

USE CASE UC-05: CREATE OFFER
-------------------------------
  Actor       : Airline Admin
  Precondition: Admin is logged in
  Flow:
    1. Admin navigates to Offers management
    2. Admin creates new offer: name, discount value, percentage/fixed,
       start date, end date, max usage count
    3. Admin assigns offer to specific flights
    4. System displays offer price alongside base price on flight search
  Postcondition: Offer is active and applied to selected flights

USE CASE UC-06: APPLY DISCOUNT CODE
--------------------------------------
  Actor       : Passenger
  Precondition: Passenger is in booking checkout
  Flow:
    1. Passenger enters discount code
    2. System validates code: active, within date range, not exceeded max uses,
       booking meets minimum amount
    3. If valid: system applies discount to total and recalculates
    4. If invalid: system shows appropriate error message
  Postcondition: Discount applied to booking total

USE CASE UC-07: AIRLINE CANCELS FLIGHT
-----------------------------------------
  Actor       : Airline Admin / Staff
  Precondition: Flight exists with confirmed bookings
  Flow:
    1. Airline staff updates flight status to Cancelled
    2. System identifies all confirmed bookings on this flight
    3. System auto-cancels all bookings
    4. System initiates full refunds (no penalty - airline's fault)
    5. System sends notification to all affected passengers
    6. System releases all seats
  Postcondition: Flight cancelled, all passengers refunded and notified

12. PRICING ENGINE LOGIC
================================================================================

Formula:
  Final Price = (Base Price per Class)
              - (Offer Discount, if flight has active offer)
              - (Discount Code, if passenger applied one)
              + (Taxes: sum of applicable TaxFee entries)
              + (Fees: sum of applicable fee entries)
              + (Extra Baggage: (requested kg - free kg) x rate per kg)

Example Calculation:
  +----------------------------------+----------+
  | Item                             | Amount   |
  +----------------------------------+----------+
  | Economy Base Price               | $200.00  |
  | Active Offer -15%                | -$30.00  |
  | Subtotal after Offer             | $170.00  |
  | Discount Code "SAVE20" (fixed)   | -$20.00  |
  | Subtotal after Discount          | $150.00  |
  | Airport Tax 10%                  | +$15.00  |
  | Service Fee (fixed)              | +$5.00   |
  | Extra Baggage 5kg x $3/kg        | +$15.00  |
  +----------------------------------+----------+
  | FINAL TOTAL                      | $185.00  |
  +----------------------------------+----------+

Rules:
  - Offers are automatic (applied if flight has active offer within date range)
  - Discount codes are manual (passenger enters code at checkout)
  - Offer discount applied before discount code
  - Taxes and fees applied after all discounts
  - Extra baggage calculated only if exceeding free allowance
  - Final price cannot be negative (minimum $0)
